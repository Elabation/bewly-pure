# 洁净B站 · 安装与使用教程

> 三分钟装好，夺回你的首页。
> 报告（为什么这么做）：https://elabation.github.io/clean-bilibili-report/web/ecosystem-report.html
>
> 本插件不登录、不上传、不碰你的账号数据——所有判定在你的浏览器里完成，只调用 B 站公开接口读取视频的公开互动数。

---

## 一、它能做什么

### PC 端 · 浏览器扩展（网格模式）

打开 bilibili.com 时，扩展把首页推荐流整个重绘为**自适应网格**：

1. **同步层（拉流即滤）**：直播、时长 ≤75 秒的短视频、标题命中「第N集/话」「挑战体」切片签名的卡片，直接不渲染；
2. **懒判定层**：卡片滚近视口时，自动调 B 站公开接口读取 收藏/投币/点赞，计算 **CBI 感谢指数**（= 加权感谢率 ÷ 同播放段基线），把「播放量很大、观众却几乎不给硬币收藏」的**「看过，却不给」**卡片**不渲染**，其余卡片右上角实时点亮 CBI 评分角标。

B 站顶栏（搜索/头像/历史/收藏/消息）**原生保留**；状态条显示实时过滤统计，点「切回原版」一键还原。

### 手机端 · m.bilibili.com 脚本

首页热榜（SSR）/ 频道流 / 视频页相关流三股全过滤，判定核心与 PC 版逐字段一致。

全部阈值可手调（见第四节）。

## 二、安装

### 方式一 · PC 浏览器扩展（Edge / Chrome，自研扩展，最推荐）

1. **拿到 `extension/` 文件夹**：打开仓库页 → 绿色 Code 按钮 → Download ZIP → 解压
2. Edge 地址栏输入 `edge://extensions` 回车（Chrome 为 `chrome://extensions`）
3. 打开左下角「**开发人员模式**」开关
4. 点顶部「**加载解压缩的扩展**」→ 选中 `extension` 文件夹
5. 打开 https://www.bilibili.com ——首页已变成网格铺平模式

更多说明（文件结构、更新方法、与原版的关系）见 [extension/README-INSTALL.md](../extension/README-INSTALL.md)。

### 方式二 · 手机端脚本（免 root）

**Android（推荐 Via / X 浏览器，体积小、自带脚本引擎）**

1. 应用商店安装 Via 浏览器 → 菜单 → 设置 → 通用 → 脚本执行 → 右上角「+」新建脚本
2. 粘贴 `userscript/bilibili-clean-mobile.user.js` 全文 → 保存
3. 用 Via 打开 `m.bilibili.com`（建议设为书签/主页）

**iOS（Safari + Userscripts App，免费开源）**

1. App Store 安装 Userscripts → Safari 设置 → 扩展 → Userscripts 允许 + 所有网站
2. 在 Userscripts App 里新建脚本，粘贴脚本全文保存
3. Safari 打开 `m.bilibili.com`

## 三、验证生效

PC 扩展装好后打开 https://www.bilibili.com ：

- 首页推荐流变成**网格铺平**布局，卡片右上角出现评分角标：`CBI 1.32 · 知识`（≥1 为达到同类平均感谢水平）或 `F7 0.081`（播放量不足 5 万时显示原始感谢率）；
- 顶部**状态条**：「洁净B站 · 网格模式 · 已过滤 N（原因明细）」；
- 按 `F12` 打开控制台，输入 `CleanBili.counts` 看实时分类统计，`CleanBili.verdicts` 看每条判定明细；
- 状态条右侧「**切回原版**」随时还原 B 站原生首页（本次会话内）。

看不到网格？见第五节 FAQ。

## 四、判定逻辑一览（对应调查报告 §13）

```
同步层（拉流即滤，卡片根本不渲染）
  直播            R1
  时长 ≤ 75s      R1        ← 短视频硬偏好
  第N集/话·挑战体  R7        ← 仅采用经过 6,734 条样本检验的标题签名（p<0.01）

懒判定层（卡片滚近视口才查详情）
  竖屏            R1 → 不渲染
  播放 < 1000     R1 → 不渲染（新稿保护线）
  官方区白名单     R4 → 电影/电视剧/纪录片 跳过 CBI（它们感谢率天然垫底，§7）
  播放 ≥ 5万 且 CBI < 0.5   R2 → 不渲染「看过不给」
  播放 3千~5万     R2'→ 全局兜底，只砍最低档 junk（low 只打标）
  「投币X更新」    R8 → 角标打「乞」标，只提醒不惩罚
```

公式（报告 §1/§6）：

```
F7  加权感谢率 = (3×收藏 + 2×投币 + 0.3×点赞) / 播放
CBI 感谢指数   = F7 ÷ 同播放段基线中位数（6,734 条样本滑窗拟合，扩展已内置曲线）
```

设计纪律：**不用 log 分母**（会把质量分变成热度探测器，§9）；**不做标题文体歧视**（emoji/感叹号/排版与感谢率无稳定关系甚至反向，§14）。

## 五、手调参数

扩展的参数在 `extension/content.js` 头部 `CONFIG`（与仓库 `config/clean.config.json` 同构）。编辑器打开 `content.js` → 改 → 保存 → `edge://extensions` 里点该扩展的「重新加载」→ 刷新 B 站生效。

| 想改什么 | 位置 | 默认 | 说明 |
|---|---|---|---|
| **CBI 判定线** | `cbi.threshold` | 0.5 | 调大（0.6）更严，调小（0.4）更宽容 |
| CBI 起判播放 | `cbi.min_view` | 50000 | 播放低于此值不做 CBI 判定 |
| 短视频判定线 | `filters.short_video_max_duration_sec` | 75 | 秒；改成 0 关闭 |
| 竖屏过滤 | `filters.portrait.enabled` | true | 竖屏内容是否过滤 |
| 播放保护线 | `filters.min_views` | 1000 | 低于此播放量直接过滤 |
| 白名单分区 | `filters.zone_whitelist` | 电影/电视剧/纪录片 | 加入「影视」等可豁免更多官方区 |
| 标题黑名单 | `filters.block_keywords` | 两条正则 | 正则数组，命中即过滤；**别加 emoji/感叹号**（无效甚至反向，§14） |
| 乞讨文本 | `filters.beggar_patterns` | 投币/三连/点赞 | 只打标不惩罚 |

## 六、FAQ

**Q：装了没反应？**
按顺序检查：① `edge://extensions` 里扩展是否处于启用状态；② 当前页面是否 `www.bilibili.com` 首页（视频播放页/空间页不处理）；③ 刷新一次首页；④ F12 控制台看有没有红色 `[CleanBili]` 报错——有的话带着截图提 issue。

**Q：上次点了「切回原版」，刷新后又变回网格了？**
「切回原版」只作用于当前会话。想永久停用：`edge://extensions` 里把扩展关掉。

**Q：把我喜欢的内容也藏了？**
角标会告诉你原因（如 `CBI 0.42`）——如果你觉得它被冤枉，把 `cbi.threshold` 调到 0.4 试试；内容属于官方区（如影视解说被划进电影区），把它加进 `zone_whitelist`。过滤哲学是「宁可放过，不可冤枉」——所有判定都可关。

**Q：会封号 / 有风险吗？**
扩展只读取 B 站公开的 view 接口（浏览器正常访问也会发的请求），不写入任何数据、不模拟登录、不碰风控接口。理论上与你手动打开视频页看数据无异。但请自担使用风险，本项目与 B 站官方无关。

**Q：为什么状态条统计和我感觉不符？**
「其他」计数包含广告卡与非视频卡（它们本来也不该出现在推荐流）。

**Q：手机端能用吗？**
能——方式二的免 root 方案（Via/X + Userscripts），判定核心与 PC 扩展一致；方案评估详见 `docs/mobile-plan.md`。

**Q：数据 / 结论可信吗？**
见调查报告：7,537 条视频、2019-2026 八年跨度（「每周必看」387 期）、十三项统计实验（偏相关、分位回归、洛伦兹/基尼、PCA、χ²、MWU 检验等），以及它们的局限说明。报告在线阅读：https://elabation.github.io/clean-bilibili-report/web/ecosystem-report.html

## 七、更新与反馈

- **更新扩展**：重新下载仓库覆盖 `extension/` 文件夹 → `edge://extensions` 里点「重新加载」→ 刷新 B 站
- **问题反馈**：GitHub 仓库提 issue（附控制台报错截图）
